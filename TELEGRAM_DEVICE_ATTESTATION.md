# Device Attestation для Telegram-транка (отложенная задача)

> Статус: **не реализовано**, зафиксировано для возврата к вопросу.
> Дата постановки: 2026-09-16

## Суть задачи

Разрешать подключение к Telegram-транку (`plugin_telegram_trunk` / `tg2sip`)
только с **подлинного официального приложения Telegram**, запущенного на
**настоящем физическом устройстве** (не эмулятор, не перепакованный APK).
Проверка должна опираться на аппаратную/платформенную аттестацию, а не на
самоподписанные данные клиента.

Это **device attestation**, а не лицензирование ПО.

## Что именно проверяем

1. APK — официальный клиент Telegram (подпись разработчика Telegram).
2. Приложение запущено на реальном устройстве (не эмулятор, без root/модификаций,
   device integrity = MEETS_DEVICE_INTEGRITY).
3. Результат аттестации подписан платформой (Google / Huawei / Apple) и проверяется
   на сервере.

## Платформы и решения

| Платформа | Сервис | Что доказывает |
|-----------|--------|----------------|
| Android (Google) | **Play Integrity API** | Подлинность приложения, целостность устройства, подлинность аккаунта |
| Android (Huawei, без GMS) | **Huawei Safety Detect / SysIntegrity** | Аналог Play Integrity для HMS-устройств |
| iOS | **Apple DeviceCheck / App Attest** | Подлинность устройства Apple и приложения |
| Альтернатива (кросс-платформа) | Firebase App Check | Обёртка над attestation-провайдерами |

### Отдельно: подпись APK Telegram
Независимо от attestation, можно проверять **сертификат подписи APK**:
официальные сборки Telegram подписаны известным ключом (SHA-256 отпечаток
сертификата). Это отсекает перепакованные/модифицированные APK, но **не**
доказывает, что устройство реальное (это делает Play Integrity).

## Архитектура проверки (черновик)

```
┌─────────────────┐  1. request nonce   ┌──────────────────┐
│ Мобильный клиент │ ──────────────────► │  Наш backend     │
│ (Telegram/tg2sip)│ ◄── nonce ───────── │  (tg2sip / panel)│
│                  │                     │                  │
│ 2. получает      │                     │                  │
│    integrity-    │                     │                  │
│    токен         │                     │                  │
│    (Play/Safety/ │                     │                  │
│     App Attest)  │                     │                  │
│                  │ 3. POST token       │                  │
│                  │ ──────────────────► │ 4. verify online │
│                  │                     │    (Google/Huawei│
│                  │ ◄── access ──────── │    /Apple API)   │
└─────────────────┘                     └──────────────────┘
```

Ключевые моменты:
- **nonce** генерируется нашим сервером и вшивается в запрос аттестации,
  чтобы токен нельзя было переиспользовать (защита от replay).
- Токен аттестации **обязательно проверяется онлайн** на сервере платформы
  (Google Play Integrity API / Huawei / Apple), а не на клиенте.
- Решение (verdict) сохраняется; доступ выдаётся только при
  `MEETS_DEVICE_INTEGRITY` + совпадении package name и сертификата подписи.

## Как это ложится в текущий проект

- Точка входа для подключения устройства — `plugins/plugin_telegram_trunk/`
  (регистрация через `tg2sip-webrtc` gateway).
- Возможное место для эндпоинта проверки:
  `POST /api/telegram/attest` (nonce) + `POST /api/telegram/attest/verify`.
- Проверку verdict можно делать в `plugin_main.py` при попытке регистрации
  телефона/шлюза.

## Ограничения и подводные камни

1. **Play Integrity API** требует Google Cloud-проект, номер проекта и
   включённый API; верификация только на сервере, ключ — service account.
2. **Huawei** — отдельный SDK и AppGallery Connect; нужен только если у клиентов
   устройства Huawei без GMS.
3. **Apple App Attest** требует server-side проверки CBOR-объекта и attestation
   сертификатов; сложнее в реализации.
4. **Root/кастомные прошивки**: Play Integrity может вернуть
   `MEETS_BASIC_INTEGRITY` вместо `MEETS_DEVICE_INTEGRITY` — нужно решить,
   какой уровень считать достаточным.
5. **Официальный Telegram не использует tg2sip**: аттестация касается *нашего*
   приложения/шлюза, которое устанавливается рядом с Telegram. Если же цель —
   проверить, что именно Telegram APK официальный, то это проверка подписи APK
   встроенными средствами ОС (Android PackageManager) + Play Integrity для
   устройства.
6. Приватность: хранение integrity-verdict и device id — персональные данные,
   нужна политика хранения.
